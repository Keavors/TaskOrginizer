# Архитектура

Приложение для Android на Kotlin и Jetpack Compose (Material 3). Речь распознаёт системная служба Android через `SpeechRecognizer`. Своих моделей и нативного кода в приложении нет, и интернет ему не нужен: разрешения на него нет.

```mermaid
flowchart LR
  UI["Compose UI<br/>MainViewModel"] --> Store["Store<br/>состояние + сохранение"]
  Store --> Disk["AppStorage<br/>JSON, AtomicFile, бэкапы"]
  UI --> Dict["DictationController"]
  Dict --> SR["SpeechRecognizer<br/>служба телефона: Google, Samsung…"]
  Dict --> Text["text/<br/>словарь, исправления"]
  Store --> Rem["Reminders<br/>один точный будильник"]
  Rem --> Notif["ReminderNotifier<br/>уведомления"]
  Alarm["ReminderReceiver<br/>будильник, кнопки, перезагрузка"] --> Rem
```

## Пакеты

| Пакет | Что внутри |
|---|---|
| `data` | модель данных (`Model.kt`), чистые операции над ней (`DataOps`), хранение на диске (`AppStorage`), состояние в памяти (`Store`) |
| `text` | обработка текста: словарь с русскими окончаниями, поиск исправлений пользователя, разбор ввода на записи |
| `speech` | диктовка через `SpeechRecognizer` (`DictationController`), службы распознавания на телефоне (`RecognitionServices`) |
| `reminders` | расписание напоминаний (`ReminderPlanner`, чистые функции), будильник и состояние (`Reminders`), уведомления (`ReminderNotifier`), приёмник событий (`ReminderReceiver`) |
| `ui` | экраны и компоненты Compose, `MainViewModel`; `DesignParts` — элементы, которые рисуются по текущему стилю |
| `ui/theme` | палитры, светлая, тёмная и чёрная темы (`Theme`), стили оформления (`Design`) |

## Данные

- Все изменения — чистые функции `DataOps`. Они возвращают новый `AppData` и покрыты тестами (`app/src/test`).
- `Store` держит состояние в `StateFlow`. Файл пишется через 300 мс после последнего изменения, а при сворачивании приложения — сразу.
- Файлы лежат в `files/data/` приложения: `data.json`, `settings.json`, `backups/`.
  - Запись атомарная, через `AtomicFile`.
  - Если файл повреждён, загружается последняя исправная копия, а сам повреждённый файл сохраняется рядом.
- Удаление идёт через корзину с `batchId`, поэтому одно «Отменить» возвращает всё, что удалено одним действием.
- JSON настроен терпимо: неизвестные поля пропускаются, неизвестные значения перечислений заменяются значениями по умолчанию. Новые версии приложения читают старые файлы.

## Распознавание речи

- **Служба.** По умолчанию — служба распознавания, выбранная в Android. В настройках можно выбрать любую установленную службу (`android.speech.RecognitionService`) или распознаватель Android 12+ на устройстве. Чтобы приложение видело службы на Android 11+, в манифесте объявлен `<queries>`.
- **Без интернета.** Запрос идёт с `EXTRA_PREFER_OFFLINE`: служба распознаёт только на телефоне. Если у неё нет языка для работы без сети, приложение говорит, что делать. Переключатель «Только без интернета» в настройках снимает это ограничение.
- **Скорость.** Распознавание потоковое: частичный текст (`onPartialResults`) виден во время речи, финальный приходит сразу после паузы или нажатия на кнопку.
- **Английские названия.** Системные службы часто пишут их по-русски («гитхаб»). Словарь заменяет такие слова с учётом падежей, а исправления пользователя приложение предлагает запомнить. На Android 13+ слова из словаря передаются службе как подсказки (`EXTRA_BIASING_STRINGS`); службы без их поддержки подсказки игнорируют.
- **Надёжность.** Для каждой фразы создаётся новый `SpeechRecognizer`, поздние ответы старого игнорируются. Если служба вернула ошибку или не прислала финальный текст за 8 секунд, сохраняется уже распознанный частичный текст.

История: первая версия распознавала речь моделью Whisper Large-v3-Turbo через whisper.cpp внутри приложения. На Galaxy S26 (Exynos 2600) модель работала только на процессоре, была медленной и неточной на живой речи, поэтому её заменили системной службой.

## Напоминания

- **Расписание.** `ReminderPlanner` по данным и настройкам считает, когда напоминает каждая запись: за N минут до срока (несколько значений), в срок, повторы после срока, пока запись не выполнена, и отложенное напоминание. Это чистые функции с тестами.
- **Один будильник.** `Reminders` держит один точный будильник (`setExactAndAllowWhileIdle` или `setAlarmClock` в «режиме будильника») на ближайшее напоминание всех записей. Когда он срабатывает, показываются все напоминания с прошлого раза, по одному на запись, и ставится следующий.
- **Без повторов и лишнего.** В `SharedPreferences` хранится момент, до которого напоминания уже показаны. Любая правка в приложении сдвигает его на «сейчас», поэтому изменённая задача не вызывает напоминаний из прошлого. После перезагрузки показываются пропущенные напоминания за последние сутки, если это включено.
- **События системы.** `ReminderReceiver` ловит будильник, кнопки уведомления «Выполнено» и «Отложить», а также перезагрузку, обновление приложения, смену времени и часового пояса и выдачу разрешения на точные будильники.
- **Уведомления.** Для каждого уровня важности свой канал, поэтому звук и вибрацию серых, жёлтых и красных задач можно настроить отдельно. Нажатие на уведомление открывает запись в её вкладке.
- **Разрешения.** `POST_NOTIFICATIONS` запрашивается, когда у записи впервые появляется время. Точные будильники разрешены через `USE_EXACT_ALARM`. В настройках есть кнопки на случай, если уведомления, точное время или фоновая работа запрещены.

## Оформление

Стиль (`DesignStyle`) меняет весь вид, а не только цвета:

- **Шрифт.** Свой встроенный шрифт у каждого стиля (`Fonts.kt`, переменные TTF из `res/font`): Manrope, Nunito, Oswald с Roboto Condensed, JetBrains Mono, Caveat, Roboto Condensed, Exo 2. «Стандарт» — системный.
- **Значки.** Своё семейство Material-значков (`AppIcons.kt`): Filled, Outlined, Rounded, Sharp или TwoTone. Экраны берут значки только из `LocalDesign.current.icons`.
- **Формы.** `Shapes` для диалогов, меню и полей: скругления, прямые углы или срезанные углы (`CutCornerShape`).
- **Элементы управления** (`Controls.kt`). Кнопки, переключатели, сегменты, чипы и радиокнопки рисуются по стилю. Это может быть пилюля, текст, квадрат, `[ текст ]`, подчёркивание «чернилами» или свечение.
- **`AppDesign`** через `LocalDesign` (`Design.kt`, `DesignParts.kt`) определяет:
  - вид записи и галочки;
  - отметку важности (флажок, точка, `!!!`, кнопка, молния);
  - вкладки, поле ввода, микрофон и верхнюю панель;
  - заголовок, фон экрана (градиент, бумага с полями, строки терминала, неоновое свечение) и разделы настроек.

Цвета складываются из палитры (акцент) и нейтральных цветов стиля. Есть тёмная и чёрная темы.

Жесты записи: нажатие открывает меню, удержание включает редактирование текста. Нажатие на пустое место главного экрана снимает фокус, курсор и клавиатура уходят.

## Как расширять

- **Новый тип вкладки** (канбан, таблица): значение в `TabKind`, своя ветка отрисовки в `ItemList`.
- **Новое поле записи** (теги, повтор задачи): поле со значением по умолчанию в `Item`, операция в `DataOps`, тест. Старые файлы читаются без миграции.
- **Новый стиль:** значение в `DesignStyle`, набор в `designOf`, нейтральные цвета, шрифт и скругления в `Theme.kt`.
- **Синхронизация между устройствами:** у сущностей есть UUID, `createdAt` и `updatedAt`, удаление идёт через корзину. Это основа для слияния изменений.
- **Другой распознаватель** (например, своя офлайн-модель): другая реализация с теми же `phase`, `partial`, `results`, что у `DictationController`; экран не меняется.
- **Глобальный голосовой ввод в любое приложение** (клавиатура или виджет): `DictationController` уже отделён от экрана.
